## 설치 없이 둘러보기 (데모 페이지)

`npm run build:demo` 를 실행하면 `dist-demo/anchor-chatbot-demo.html` 한 장짜리 데모가 만들어집니다. 실제 화면 코드에 **브라우저 안에서 도는 가짜 서버와 테스트 모델**(`web/src/demo/`)을 붙인 것으로, 가상 데이터로 사용자·검수자·관리자 화면을 모두 눌러 볼 수 있습니다 (파일 업로드·엑셀 받기는 안 됨, 새로고침하면 초기화). 검색은 실제 서버와 같은 키워드 검색 코드를 씁니다.

## 처음 실행하기 (내 컴퓨터에서 확인)

필요한 것: [Node.js](https://nodejs.org) 20 이상 (LTS 버전 설치)

```bash
npm install                # 처음 한 번만
cp .env.example .env       # 설정 파일 만들기 (Windows: copy .env.example .env)
npm run dev                # 실행
```

브라우저에서 **http://localhost:5173** 을 엽니다.

- 처음에는 `.env`의 `LLM_PROVIDER=mock`(테스트 모드)라서 AI 비용 없이 화면만 확인할 수 있습니다.
- 실제 AI를 쓰려면 `.env`에서 아래처럼 바꾸고 다시 실행하세요.
  - Gemini: `LLM_PROVIDER=gemini`, `GEMINI_API_KEY=발급받은 키`
  - Claude: `LLM_PROVIDER=claude`, `ANTHROPIC_API_KEY=발급받은 키`
- API 키는 `.env`에만 넣습니다. `.env`는 저장소에 올라가지 않습니다.

## 1단계 확인 순서 (눌러볼 화면)

1. **관리자 첫 로그인**: 아이디 `admin`, 비밀번호는 `.env`의 `ADMIN_INITIAL_PASSWORD`(기본 `change-me-1234`) → 새 비밀번호 설정 화면이 나오는지 확인
2. **가입 신청**: 다른 브라우저(또는 시크릿 창)에서 ‘가입 신청’ → 소속 구분·기관명·지역·사업 유형만 입력하는지 확인
3. **승인**: 관리자 화면 상단 **관리** → ‘가입 승인 대기’에서 승인. 권한(사용자/검수자/관리자) 변경도 해 보기
4. **질문**: 승인된 계정으로 로그인 → 상단 사업 유형 확인 → 질문 입력 → 답변 끝에 면책 문구가 붙는지 확인
5. **대화 목록**: 왼쪽 목록에서 제목 자동 생성, 검색, 삭제 확인
6. **재단에 문의하기**: 답변 아래 ‘재단에 문의하기’ (챗봇 답변을 받은 대화에서만 문의할 수 있음) → 문의 등록 → 관리자 **문의 관리**에서 ‘첨부된 대화 보기’로 대화가 함께 왔는지 확인 → 답변 등록 → 사용자 쪽 **1:1 문의**에서 답변 확인
7. **대화 열람**: 관리 → 대화 열람에서 사용자 대화를 읽기 전용으로 보기 (모델·토큰·응답 시간 표시)
8. **프롬프트 수정**: 관리 → 프롬프트·면책 문구에서 수정·저장 → 변경 이력에서 이전 버전으로 되돌리기
9. **잠금**: 일반 계정으로 비밀번호를 10번 틀리면 잠김 → 관리자가 ‘잠금 해제’ / 비밀번호 초기화(임시 비밀번호 발급) 확인
10. **다크모드·모바일**: 상단 달 아이콘, 휴대폰 화면에서도 확인

## 2단계 확인 순서 (지식 데이터)

관리자로 로그인 → 상단 **관리** → **지식 데이터** 탭

1. **표준 Q&A**: [양식 받기]로 형식 확인 → [엑셀 올리기]로 ‘통합질의’ 시트가 있는 엑셀 업로드 → ‘미리보기’ 버전의 건수(확정·미검수·연결형)와 경고(개인정보·빈 칸·중복 번호) 확인 → **[서비스에 적용]**
2. **되돌리기**: 새 엑셀을 또 올려 적용한 뒤, 이전 버전의 [이 버전으로 되돌리기]
3. **지침·FAQ 원문**: 문서 이름·종류(지침/FAQ)를 고르고 PDF 업로드 → [조항 보기]로 ‘제N조’ 단위로 잘 나뉘었는지, 쪽수가 맞는지 확인. 임시 문서는 ‘사용 중지’
4. **답변 원칙**: 엑셀(‘원칙’ 열) 또는 TXT를 [파일에서 불러오기] → 편집기에서 확인 → [저장]
5. **답변범위 외 목록**: 엑셀(대표 질의·안내 문구·담당 부서) 업로드
6. **검색 설정·시험**: 질문을 넣고 [검색] → 어떤 표준답안이 몇 점으로 찾아지는지, ‘근거 있음/없음’ 판정 확인. 필요하면 기준값 조정. 미검수 답안 사용 여부도 여기서 켜고 끔
7. **챗봇에서 질문**: 답변 아래 **참고한 근거** 카드(통합번호·대표 질의, 누르면 답안 전문)가 나오는지, 엉뚱한 질문은 ‘근거 없음’, 범위 외 질문은 ‘답변 범위 아님’으로 AI 호출 없이 처리되는지 확인
8. **대화 열람**: 관리 → 대화 열람에서 답변마다 검색된 통합번호와 토큰 사용량 확인

### 의미 검색 켜기 (선택)

키워드 검색은 바로 동작합니다. 뜻이 비슷한 다른 표현까지 찾는 의미 검색은 모델 파일(약 120MB)이 필요합니다.

```bash
npm run download-model   # 인터넷이 되는 곳에서 한 번 (models/ 폴더에 저장)
```

서버를 다시 시작하면 관리 → 지식 데이터 상단의 검색 방식이 ‘키워드 + 의미’로 바뀝니다. 서버가 인터넷이 안 되면 다른 컴퓨터에서 받은 `models/` 폴더를 서버의 같은 위치에 복사하세요. Docker로 설치하면 이미지를 만들 때 자동으로 받습니다.

## 3단계 확인 순서 (라우팅·안전장치)

1. **질문 상한**: 관리 → 시스템 정보 → ‘질문 상한’에서 1명당·전체 하루 질문 수 설정 (0 = 제한 없음, 한국 시간 0시 초기화)
2. **답변 유형별 화면** (일반 사용자 계정으로 확인)
   - 근거 답변: 초록 표시 + 근거 카드
   - 확인 필요(연결): 근거 답안이 ‘연결형’일 때. 노란 상자에 ‘지역앵커센터에 문의하시기 바랍니다.’ + [재단에 문의하기] (연락처는 보여주지 않음)
   - 답변 범위 아님 / 근거 없음: AI를 부르지 않고 안내 + [재단에 문의하기]
3. **개인정보**: 질문에 `010-1234-5678` 같은 번호를 넣고 보내기 → 경고 창 → [가리고 보내기]를 누르면 `[전화번호]`로 바뀌어 저장됩니다. (화면 경고를 거치지 않아도 서버가 한 번 더 가립니다)
4. **상한 도달**: 상한을 작게(예: 3) 바꾼 뒤 질문을 계속 보내 안내 문구와 입력창 아래 ‘오늘 질문 n/3’ 표시 확인

## 4단계 확인 순서 (평가)

관리 → **평가** 탭

1. [양식 받기]로 평가 질문집 양식 확인 → 질문 · 사업 유형 · 기대 통합번호 · 기대 유형을 채워 [엑셀 올리기]
2. 질문집의 **[실행]** → 이름(예: ‘기준선’) 입력. 근거가 있는 질문마다 AI를 1번씩 부르므로 **실제 키를 쓰면 비용이 발생**합니다. 진행 막대가 끝나면 점수가 나옵니다
3. [결과 보기] → ‘틀린 것만’으로 놓친 문항 확인. **근거답변은 모두 펼쳐 읽고 ‘적절’ / ‘잘못된 결론’으로 판정** (판정이 남아 있으면 ‘검수 대기’)
4. 프롬프트·답변 원칙·표준답안·기준값을 고친 뒤 다시 실행 → 두 실행을 체크해 **비교** (바뀐 조건, 점수 변화, 결과가 달라진 문항)
5. 위쪽 ‘시범운영 통과 기준’(기본: 인용 적중률 80% + 근거답변 전부 검수 + 잘못된 결론 0건 + 오류 0건)을 넘으면 ‘통과’ 표시

점수 읽는 법: **검색 적중**은 높은데 **인용 적중**이 낮으면 모델·프롬프트 쪽, 둘 다 낮으면 검색 기준값이나 표준답안(대표 질의·요지) 쪽을 손봅니다.

## 5·6단계 확인 순서 (운영 루프·마무리)

1. **답변 평가**: 일반 사용자로 질문 → 답변 아래 👍/👎. 👎는 사유(틀린 내용·답이 부족·근거가 엉뚱함·연결이 부적절)와 의견을 남김
2. **검토 대기함**: 검수자·관리자 상단 **검수** → 👎 답변과 ‘근거 없음’·‘범위 아님’ 질문이 모여 있음 → ① 기존 답안 수정 ② 새 답안 추가 ③ 무시
3. **표준답안 관리**: 검수 → 표준답안 관리에서 검색·필터·편집·추가·삭제, 시계 아이콘으로 수정 이력(바뀐 부분 비교) 확인. 저장 즉시 챗봇에 반영
4. **자주 묻는 질문**: 새 대화 첫 화면에 중분류별 대표 질문 버튼 (누르면 바로 질문)
5. **사용량·비용**: 관리 → 사용량·비용 (일별 질문, 추정 비용, 답변 유형 비율, Good/Bad, 기관별). 아래에서 모델 단가 입력
6. **답변 모아보기**: 관리 → 답변 모아보기 (Bad·연결형·근거 없음·범위 외만 골라 보기)
7. **공지**: 관리 → 공지에서 개정 공지 게시 + 관련 통합번호/중분류에 ‘재검수 필요’ 표시 → 챗봇 위쪽 배너, 검수 → 표준답안 관리 ‘재검수 필요만’
8. **감사 로그**: 관리 → 감사 로그 (권한 변경·데이터 교체·설정 변경·표준답안 편집 등)
9. **대화 보관 기간**: 관리 → 시스템 정보에서 일수 지정 (0 = 삭제 안 함)

## 운영 참고

- **관리자 비밀번호를 잊었거나 관리자 계정이 잠겼을 때**: 서버에서 `npm run reset-admin -- admin` 실행 → 임시 비밀번호 발급
- **데이터 백업**: DB는 `data/chatbot.db` 파일 하나입니다. 하루 한 번 `backups/` 에 자동 백업되고(14개 보관), 관리 → 시스템 정보 → '지금 백업'이나 `npm run backup` 으로 바로 만들 수 있습니다. 되살리기는 서비스를 멈춘 뒤 `npm run restore -- <백업 파일>`.
- **비밀번호 규칙**: 8자 이상, 영문과 숫자 포함. 서버에는 해시로만 저장됩니다.
- **로그인 유지 시간**: `.env`의 `SESSION_HOURS` (기본 8시간)

## 서버에 설치하기 (Docker)

```bash
cp .env.example .env      # 값 채우기 (LLM_PROVIDER, API 키, 관리자 임시 비밀번호 등)
docker compose up -d --build
```

데이터는 `./data`, 자동 백업은 `./backups` 폴더에 저장됩니다. 상태 확인: `http://서버주소:3000/api/health`

브라우저에서 `http://서버주소:3000` 으로 접속합니다. 외부에 공개할 때는 HTTPS·요청 제한·관리 메뉴 IP 제한 설정을 [`docs/서버이전·외부공개.md`](docs/서버이전·외부공개.md)의 점검표대로 맞추세요.
