# 앵커 사업비 챗봇 운영 설명서

이 문서는 개발자가 아닌 운영 담당자(관리자·검수자)를 위한 안내서입니다. 화면 이름은 굵게 표시했습니다.

---

## 1. 한눈에 보기

| 누가 | 주로 하는 일 | 쓰는 화면 |
| --- | --- | --- |
| 사용자 (대학·지역앵커센터·재단 직원) | 질문, 답변 평가(👍/👎), 담당자에게 문의 | **챗봇**, **1:1 문의** |
| 검수자 | 검토 대기함 처리, 표준답안 수정·추가, 1:1 문의 답변 | **검수**, **문의 관리** |
| 관리자 | 위 전부 + 가입 승인·권한, 지식 데이터, 평가, 설정, 통계 | **관리** |

챗봇이 답하는 순서:
1. 질문에 전화번호·이메일 등이 있으면 가린다.
2. 표준답안·지침에서 관련 항목을 찾는다. 한 메시지에 질문이 여럿이면(‘A는? B는?’, ‘A인지, 또 B인지’, ‘1. … 2. …’, ‘A랑 B 알려주세요’) 나눠서 각각 찾고, 답변도 번호를 매겨 각각 한다.
   - 관련 항목이 없으면 → **근거 없음** (AI를 부르지 않음, 검토 대기함으로)
   - 답변범위 외 목록과 비슷하면 → **범위 아님** (AI를 부르지 않음, 검토 대기함으로)
3. 찾은 항목만 AI에 넘겨 답을 만든다 → **근거 답변** 또는 **확인 필요(연결)**
4. 답변 아래에 참고한 근거 카드, 답변 기준(예: ‘기준: 중복질의_통합_표준답안초안_5차 (26. 10. 30. 적용)’), 문의처 안내(예: ‘지역앵커센터에 문의하시기 바랍니다.’, 연락처는 표시하지 않음), 고정 면책 문구가 붙는다.
5. 답변 아래 **답변 복사**를 누르면 본문·근거 번호·기준·면책 문구가 함께 복사된다. 지역앵커센터가 대학에 회신할 때 그대로 붙여 쓰면 된다.
6. 1:1 문의에 답변이 달리면 사용자 화면 상단 ‘1:1 문의’ 옆에 숫자가 뜨고, 목록에 ‘새 답변’ 표시가 붙는다.

## 2. 처음 설치할 때 (한 번만)

1. `.env.example` 파일을 복사해 `.env`를 만들고 값을 채웁니다.
   - `ADMIN_INITIAL_PASSWORD`: 최초 관리자 임시 비밀번호
   - `LLM_PROVIDER`: `gemini` 또는 `claude` (`mock`은 시험용 가짜 답변)
   - 해당 API 키 (`GEMINI_API_KEY` 또는 `ANTHROPIC_API_KEY`)
   - HTTPS로 서비스하면 `COOKIE_SECURE=true`
2. 실행합니다. (정보화 담당자에게 요청)
   - Docker: `docker compose up -d --build`
   - 직접: `npm install` → `npm run build` → `npm start`
3. 브라우저에서 접속 → `admin` / 임시 비밀번호로 로그인 → 새 비밀번호 설정
4. **관리 → 지식 데이터**
   - 표준 Q&A 엑셀 업로드 → 미리보기 확인 → **서비스에 적용**
   - 지침·FAQ PDF 업로드 → 조항 보기로 확인 → **[임시] 프로토타입 문서는 사용 중지**
   - 답변 원칙, 답변범위 외 목록 업로드
5. **관리 → 사용량·비용**: 쓰는 AI 모델의 단가 입력 (비용 계산용)
6. **관리 → 평가**: 평가 질문집을 실행해 통과 기준을 넘는지 확인한 뒤 시범운영 시작

## 3. 매일·매주 할 일

### 매일 (검수자)
- **검수 → 검토 대기함**: 상단 ‘검수’ 옆 숫자가 처리할 건수입니다.
  - **Bad 평가**: 사용자 의견을 읽고 답안이 틀렸거나 부족하면 ① 기존 답안 수정
  - **근거 없음**: 자주 나오는 질문이면 ② 새 답안 추가, 범위 밖이거나 엉뚱한 질문이면 ③ 무시
  - **보안 의심**(빨간 표시): 챗봇 지시를 바꾸거나 내부 자료를 빼내려는 질문을 막은 기록입니다. 같은 계정이 반복하면 관리 → 사용자에서 잠그고, 정상 질문이 잘못 막혔다면 개발 쪽에 알려 주세요. 감사 로그에도 '보안 의심 질문 차단'으로 남습니다.
  - 저장하면 **다음 질문부터 바로** 챗봇에 반영됩니다.
- **문의 관리**: 답변 대기 문의에 답변 등록 (첨부된 대화를 펼쳐 보면 맥락을 알 수 있습니다)
  - 다른 기관도 물을 만한 문의라면 답변 아래 **표준답안으로 등록** → 문의 내용과 답변이 채워진 편집 창에서 통합번호·분류를 넣고 저장. 다음 질문부터 챗봇이 바로 답합니다. 등록한 문의에는 ‘표준답안 ○○로 등록됨’이 표시됩니다.

### 매주 (관리자)
- **관리 → 사용량·비용**: 질문 수, 추정 비용, 근거 없음 비율, Bad 평가 사유 확인
  - ‘근거 없음’ 비율이 높으면 → 표준답안이 부족하거나 검색 기준값이 높은 것
  - Bad 사유 ‘근거가 엉뚱함’이 많으면 → 대표 질의·요지 체크리스트를 보완
- **관리 → 답변 모아보기**: Bad·연결형·근거 없음·보안 의심 답변을 훑어보기

### 매월 (관리자)
- **관리 → 사용량·비용 → 월간 운영 보고서**: 월을 고르고 엑셀 받기. 요약(질문 수, 답변 유형 비율, 👍/👎, 문의 처리 시간, 보안 차단, 추정 비용) · 일별 · 지역·소속별 · 많이 묻는 주제 · 근거 없음 질문 · 1대1 문의 시트로 내부 보고에 씁니다.

## 4. 데이터를 바꿀 때

### 표준 Q&A를 엑셀로 크게 바꿀 때
1. **검수 → 표준답안 관리 → 엑셀 내보내기**로 **현재 서비스 중인 최신본**을 받습니다. (화면에서 고친 내용이 들어 있습니다)
2. 엑셀에서 고칩니다. (‘통합질의’ 시트, 머리글 그대로)
3. **관리 → 지식 데이터 → 표준 Q&A → 엑셀 올리기** → 미리보기의 건수·경고 확인 → **서비스에 적용**
4. 문제가 생기면 이전 버전의 **이 버전으로 되돌리기**

> 주의: 1번을 건너뛰고 옛날 엑셀을 올리면 화면에서 고친 내용이 빠진 버전이 적용됩니다.

### 지침이 개정되었을 때
1. **관리 → 지식 데이터 → 지침·FAQ 원문**: 개정판 PDF 업로드 → 이전 판 **사용 중지**
2. **관리 → 공지**: 개정 내용을 공지하고, 영향받는 표준답안의 통합번호나 중분류를 적어 **재검수 필요** 표시
3. **검수 → 표준답안 관리 → ‘재검수 필요만’**: 하나씩 열어 확인·수정 후 저장 (저장하면 표시가 사라짐)
4. **관리 → 평가**: 같은 질문집을 다시 실행해 점수가 떨어지지 않았는지 비교

### 프롬프트·답변 원칙을 바꿀 때
1. **관리 → 평가**에서 바꾸기 전 실행 결과가 있는지 확인 (없으면 먼저 실행)
2. **관리 → 프롬프트·면책 문구** 또는 **지식 데이터 → 답변 원칙**에서 수정·저장
3. 평가를 다시 실행 → 두 실행을 체크해 **비교** → 나빠졌으면 **변경 이력 → 이 버전으로 되돌리기**

## 5. 평가 점수 읽는 법

| 점수 | 뜻 | 낮을 때 손볼 곳 |
| --- | --- | --- |
| 인용 적중 | 기대한 표준답안을 근거로 인용했는가 | 아래 두 줄로 원인을 가립니다 |
| 검색 적중 | 기대한 표준답안이 검색 결과에 있었는가 | 낮으면: 대표 질의·요지 체크리스트 보완, 키워드 기준값 낮추기 |
| (검색 적중 높고 인용 적중 낮음) | 찾았는데 AI가 안 씀 | 프롬프트·답변 원칙 |
| 연결 정확 | 답하면 안 되는 질문을 걸러냈는가 | 답변범위 외 목록 보완, 연결형 표시 확인 |
| 잘못된 결론 | 검수자가 읽고 틀렸다고 표시한 건수 | 해당 표준답안·원칙 수정 (0건이어야 통과) |

통과 기준(기본): 인용 적중 80% 이상 + 근거답변 전부 검수 + 잘못된 결론 0건 + 오류 0건

## 6. 계정 관리

- **가입 승인**: 관리 → 사용자·권한 위쪽 ‘가입 승인 대기’에서 승인/거절
- **계정 일괄 등록**: 관리 → 사용자·권한 → **일괄 등록** → 양식 받기 → 아이디·소속 구분·기관명·지역(사업 유형·권한은 선택)을 적어 올리기. 한 번에 500명까지. 잘못된 행은 사유가 표시되고 나머지만 만들어집니다. 나온 임시 비밀번호 목록은 창을 닫으면 다시 볼 수 없으니 **복사**해서 각 기관에 전달하세요.
- **권한**: 사용자 / 검수자 / 관리자. 마지막 관리자는 권한을 내릴 수 없습니다.
- **비밀번호 분실**: 사용자 행의 열쇠 아이콘 → 임시 비밀번호를 전달 → 첫 로그인 때 바꾸게 됨
- **10회 실패 잠금**: 사용자 행의 ‘잠금 해제’
- **관리자 본인이 잠겼거나 비밀번호를 잊었을 때**: 서버에서 `npm run reset-admin -- admin` (정보화 담당자에게 요청)
- 관리 작업은 모두 **관리 → 감사 로그**에 남습니다.

---

## 7. 비용 관리

- **관리 → 시스템 정보 → 질문 상한**: 사용자 1명당 / 전체 하루 질문 수 (한국 시간 0시 초기화)
- **관리 → 사용량·비용**: 단가를 쓰는 모델에 맞게 넣어야 추정 비용이 맞습니다.
- 근거 없음·범위 아님 답변은 AI를 부르지 않아 비용이 들지 않습니다.
- 평가 실행은 질문 수만큼 AI를 부릅니다.

---

## 8. 개인정보와 보관

- 가입 때 이름·연락처를 받지 않습니다. 질문 속 전화번호·이메일·주민번호·계좌번호는 저장 전에 가려집니다.
- **관리 → 시스템 정보 → 대화 보관 기간**: 정한 일수가 지난 대화는 자동 삭제됩니다 (0 = 삭제 안 함). 기록물 관리 기준에 맞춰 정하세요.
  1:1 문의에 첨부된 대화 사본은 문의와 함께 남습니다.
- 표준 Q&A는 비식별 처리된 데이터만 올립니다. 업로드 때 전화번호·이메일이 보이면 경고가 뜹니다.

## 9. 백업과 복구

- 모든 데이터는 `data/chatbot.db` 파일 하나에 있습니다 (Docker는 `./data` 폴더).
- **자동 백업**: 하루 한 번 `backups` 폴더에 백업 파일이 쌓이고, 최근 14개만 남습니다. 서비스를 멈출 필요가 없습니다.
- **지금 백업**: 관리 → 시스템 정보 → **지금 백업**. 서버 이전·업데이트 전에 눌러 두세요.
- `backups` 폴더는 주기적으로 다른 디스크나 외부 저장소에 복사해 두는 것이 안전합니다.
- **복구**: 서비스를 멈춘 뒤 백업 파일로 되살립니다. 자세한 명령은 [서버 이전·외부 공개 안내](서버이전·외부공개.md)를 보세요.

## 10. 문제가 생겼을 때

| 증상 | 확인할 것 |
| --- | --- |
| 화면 위에 ‘테스트 모드’ 노란 띠 | `.env`의 `LLM_PROVIDER`가 `mock`임 → `gemini`/`claude`와 키 입력 후 재시작 |
| “AI 응답을 받지 못했습니다” | API 키·사용 한도·네트워크(외부 AI 접속 허용 여부) 확인. 서버 로그에 상세 오류 |
| 거의 모든 질문이 ‘근거 없음’ | 표준 Q&A를 ‘서비스에 적용’했는지, 검수상태가 ‘확정’인지, 키워드 기준값이 너무 높지 않은지 (지식 데이터 → 검색 설정·시험) |
| 엉뚱한 근거가 붙음 | 검색 시험으로 점수 확인 → 대표 질의·요지 보완, 기준값 올리기 |
| 엑셀 업로드 “머리글을 찾지 못했습니다” | ‘통합질의’ 시트의 머리글 이름 확인 (통합번호·대표 질의·통합 답안 필수) |
| PDF 업로드 “글자를 읽지 못했습니다” | 스캔 이미지 PDF임 → 글자가 들어 있는 PDF로 다시 저장. 한글(HWP)은 PDF로 저장 |
| 검색 방식이 ‘키워드만’ | 의미 검색 모델이 없음 → `npm run download-model` 후 재시작 (선택 사항) |
