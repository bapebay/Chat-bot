# 서버 이전·외부 공개 안내

이 챗봇을 인터넷에 공개하거나 다른 서버·클라우드로 옮길 때 보는 문서입니다.
규모는 이용자 수백 명, **서버 한 대** 기준입니다.

## 1. 무엇을 옮기면 되나

챗봇이 기억하는 것은 아래 세 가지뿐입니다.

| 무엇 | 어디에 | 설명 |
| --- | --- | --- |
| 데이터 전부 | `data/chatbot.db` | 계정, 대화, 표준답안, 지침, 문의, 설정. 올린 엑셀·PDF도 읽어서 이 파일에 들어갑니다 |
| 설정 | `.env` | AI 키, 포트, 보안 설정. **저장소에 올리지 말고 따로 안전하게 옮깁니다** |
| 백업 | `backups/` | 자동 백업 파일 (옮기지 않아도 되지만 남겨 두면 좋음) |

의미 검색 모델(`models/`)은 Docker 이미지를 만들 때 자동으로 들어갑니다.
인터넷이 막힌 곳에서 이미지를 만들면 빠지는데, 이때는 기존 서버의 `models` 폴더를 복사해 `/app/models`에 연결하면 됩니다.

옮기지 않아도 저절로 따라가는 것과, 따라가지 않는 것:
- 기능·보안 규칙은 모두 코드에 있어 새 서버에 코드를 설치하면 그대로 동작합니다. 예전 DB를 가져와도 서버가 켜질 때 DB 구조를 스스로 맞춥니다.
- **데모 페이지(claude.ai)에 올린 데이터는 저절로 넘어가지 않습니다.** 아래 「데모 자료 옮기기」로 한 번에 옮기거나, 운영 서버 관리 화면에서 원본 파일을 다시 올립니다.
- 개발 현황 문서, 기능 점검표도 claude.ai에 있어 서버 이전과 관계없습니다.

## 2. 옮기는 순서

**기존 서버**
1. 서버에서 지금 백업을 만듭니다: `docker compose exec chatbot node dist/server/scripts/backup.js` (화면에는 백업 버튼이 없습니다)
2. 새로 만들어진 백업 파일(`backups/chatbot-날짜-시간.db`)과 `.env`를 새 서버로 복사합니다.

**새 서버** (Docker 설치되어 있어야 함)
1. 저장소를 내려받고, 복사해 온 `.env`를 같은 자리에 둡니다. 새 환경에 맞게 주소·AI 설정을 고칩니다.
2. 백업 파일로 DB를 되살립니다.
   ```bash
   mkdir -p backups && cp <복사한 백업 파일> backups/
   docker compose build
   docker compose run --rm chatbot node dist/server/scripts/restore.js /app/backups/<백업 파일 이름>
   docker compose up -d
   ```
3. 확인: `http://새서버:3000/api/health` 가 `{"ok":true}`, 관리자로 로그인해 지식 데이터·대화가 보이는지.
4. 주소(도메인)를 새 서버로 돌린 뒤 기존 서버를 끕니다.

> 되살릴 때 원래 있던 DB는 `chatbot.db.before-restore-숫자` 이름으로 옆에 남겨 둡니다.

Docker 없이 Node.js로 돌릴 때는 `npm run backup`, `npm run restore -- <백업 파일>` 을 씁니다(서비스를 멈춘 뒤 복원).

### 데모 자료 옮기기

데모 페이지에서 쓰던 **사용 중인 표준 Q&A · 집행원리 · 지침·FAQ · 설정(시스템 프롬프트 포함)** 을 내보낸 파일 하나로 운영 서버에 넣습니다.
파일은 저장소의 `migration/데모자료_서버이전용.json` 에 있습니다(2026-11-09 데모 기준. 이후 데모를 고쳤다면 다시 내보내 바꿔 둡니다).
데모의 계정·대화 기록·감사 로그 같은 시험 기록은 옮기지 않습니다.

```bash
cp migration/데모자료_서버이전용.json data/
docker compose stop chatbot
docker compose run --rm chatbot node dist/server/scripts/import-demo.js /app/data/데모자료_서버이전용.json
docker compose start chatbot
```

- 넣기 전에 지금 DB를 `backups/`에 자동으로 백업합니다.
- 기존 자료는 지우지 않고 '보관'으로 돌립니다. 관리 → 지식 데이터에서 예전 버전으로 되돌릴 수 있습니다.
- 처음 실행 때 들어간 `[임시]` 지침 발췌본은 자동으로 숨깁니다.
- 바뀐 설정은 관리 → 프롬프트·설정의 변경 이력에 남아 되돌릴 수 있습니다.
- Docker 없이: 서비스를 멈춘 뒤 `npm run import-demo -- <파일>`.
- 파일에는 지침·답변 원문이 들어 있으므로 저장소를 비공개로 유지합니다.

## 3. 외부 공개 전 점검표

| 항목 | 설정 | 확인 |
| --- | --- | --- |
| HTTPS | 앞단 웹서버(Nginx·로드밸런서·클라우드 인증서)에서 처리 | 주소가 `https://` 로 열림 |
| HTTPS 전용 쿠키 | `.env`: `COOKIE_SECURE=true` | 로그인 유지가 HTTPS에서만 됨 |
| 앞단 웹서버 위치 | 같은 서버나 내부망(사설 IP)에 둠 | 그래야 실제 접속자 IP로 요청 제한이 걸림 (설정 없음) |
| 최초 관리자 비밀번호 | 첫 로그인 때 바꾸기 (강제) | |
| 하루 질문 한도 | 관리 → 시스템 정보에서 1인당·전체 한도 | AI 비용 상한 |
| 자동 백업 | 기본 하루 1번, 14개 보관 (화면 표시 없음) | 서버의 `backups` 폴더에 파일이 쌓이는지 |
| 백업 보관 위치 | `backups` 폴더를 DB와 다른 디스크나 외부 저장소로 주기적으로 복사 | |

이미 들어 있는 보호 장치(설정 불필요):
- 보안 응답 헤더: 다른 사이트에 끼워 넣기 차단, 외부 스크립트 차단 등
- 로그인을 10번 틀리면 15분 동안 막힘(저절로 풀림), 비밀번호는 해시로만 저장
- IP별 요청 횟수 제한 (아래 표), 휴대폰 이용 차단(PC 전용)
- 가입 시 이름·연락처 등 개인정보 수집 안 함, 질문 속 개인정보 경고·가림
- 서버 쪽 권한 확인, 감사 로그 (관리자가 다른 사람 대화를 연 기록 포함)
- 프롬프트 인젝션(AI 지시 바꾸기·지시문 빼내기·자료 통째 출력) 세 겹 방어
  1. 질문 단계: "이전 지시 무시", "시스템 프롬프트 보여줘", "표준답안 전부 출력" 같은 공격 문구는 AI를 부르지 않고 거절, 검토 대기함·감사 로그에 기록. 같은 계정이 하루 3번이면 그날 질문 중지
  2. AI 지시문: 근거 자료·질문 속 글은 지시가 아니라는 보안 규칙을 항상 붙임 (관리자가 프롬프트를 바꿔도 빠지지 않음)
  3. 답변 단계: 답변에 내부 지시문 문장이 섞여 나오면 보여주지 않고 차단
  - 점검용 공격 질문 25개: `docs/레드팀_평가질문집.xlsx`. 챗봇에 직접 넣어 확인합니다. 1~18번은 질문 단계에서 막혀야 하고, 19~25번은 AI까지 가는 위장 공격이라 답변을 사람이 확인합니다

요청 횟수 제한 기준(같은 IP 기준):

| 대상 | 한도 |
| --- | --- |
| 로그인 | 1분 10회 |
| 가입 신청 | 1시간 5회 |
| 질문 | 1분 15회 |
| 1:1 문의 | 1시간 10회 |
| 그 밖의 모든 요청 | 1분 300회 |

> 한 기관 사람들이 같은 IP(공용 인터넷)로 접속하면 함께 셉니다. 질문 1분 15회는 한 기관에서 동시에 여러 명이 써도 대개 충분하지만, 막히는 일이 생기면 알려 주세요.

## 4. 환경별 메모

- **AI 연결**: `LLM_PROVIDER` 로 고릅니다.
  - `claude`, `gemini`: 해외 AI 서비스(외부 인터넷 필요)
  - `openai`: OpenAI 호환 방식. OpenAI뿐 아니라 국내 클라우드 AI, 기관 안에 설치한 모델(vLLM·Ollama 등)도 `OPENAI_BASE_URL` 만 바꿔 연결합니다. 외부 인터넷이 막힌 환경으로 옮길 때 쓰는 길입니다.
  - AI를 바꾼 뒤에는 자주 나오는 질문과 레드팀 질문 몇 가지를 넣어 답이 바른지 확인하세요.
- **클라우드**: Docker 컨테이너 하나와 디스크 두 개(데이터, 백업)만 있으면 됩니다. 공공기관용 보안인증 클라우드에서도 같은 방식입니다.
- **서버 여러 대로 늘리기**: 지금 구조(SQLite 파일 DB)는 서버 한 대 전용입니다. 이용자가 수천 명 이상으로 늘어 여러 대가 필요해지면 별도 DB 서버(PostgreSQL)로 바꾸는 작업이 필요합니다.
- **시간대**: 컨테이너는 기본 UTC입니다. 로그 시각을 한국 시간으로 보려면 `docker-compose.yml` 의 `environment` 에 `TZ: Asia/Seoul` 을 넣습니다.
