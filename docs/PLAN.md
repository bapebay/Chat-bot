# 앵커 사업비 챗봇 — 기술 구성 제안 및 단계별 작업 계획 (초안)

> 기준 문서: `docs/앵커 사업비 챗봇 기능설명서.md`, 기존 프로토타입: `docs/reference/smart_anchor_assistant.jsx`
> 상태: 계획 승인됨 (2026-10-29). 1단계 완료 — 진행 상황은 README 참고.

## 1. 기술 구성 제안 (비용 최소화 기준)

| 구분 | 제안 | 이유 |
| --- | --- | --- |
| 화면(프론트엔드) | React + Vite + Tailwind | 기존 프로토타입이 React·Tailwind라 화면을 거의 그대로 옮길 수 있음. 다크모드 유지 |
| 서버(백엔드) | Node.js + TypeScript (Fastify) | 화면과 같은 언어. API 키·모델 호출·권한 확인을 모두 서버에서 처리 |
| DB | SQLite (파일 1개) | 별도 DB 서버 불필요 → 비용 0원, 백업은 파일 복사. 사용자 수천 명·답안 2,000건 규모에 충분 |
| 키워드 검색 | SQLite FTS5 (trigram, 한국어 부분일치) | 추가 비용 없음 |
| 의미 검색 | 서버 내장 다국어 임베딩 모델(multilingual-e5 계열, 서버에서 직접 실행) + 메모리 내 유사도 계산 | 외부 임베딩 API 비용 0원, 질문이 추가 업체로 나가지 않음. 2,000건은 벡터 DB 없이 수 ms 안에 검색 |
| AI 모델 | 제공사 교체형 어댑터(Gemini / Claude). `.env`에서 제공사·모델명·API 키 지정 | 설명서 10장 결정사항 대비. 가벼운 모델로 시작해 평가 질문집 점수로 올림 |
| 엑셀 처리 | SheetJS(xlsx) | ‘통합질의’ 시트 업로드·내보내기 |
| 인증 | 아이디/비밀번호(bcrypt 해시) + 서버 세션 쿠키(만료 시간) | 10회 실패 잠금·강제 변경 유지 |
| 배포 | Docker 이미지 1개 (서버가 화면까지 함께 제공) | 재단 내부 서버든 클라우드 VM이든 같은 방식으로 설치 |

### 월 예상 비용

질문 1건당 모델 입력 ≈ 답변 원칙 4천 토큰 + 검색 상위 8건 4~5천 토큰 + 최근 대화 1천 토큰 ≈ **1만 토큰**, 출력 ≈ **1천 토큰**으로 추정.

| 모델 예시 | 1건당 비용 | 월 1천 건(1단계 내부) | 월 2만 건(3단계 확대) |
| --- | --- | --- | --- |
| 경량 모델 (예: Claude Haiku 5.5, $0.10/$0.50 per 1M) | 약 $0.0015 (≈2원) | 약 $2 (≈3천 원) | 약 $30 (≈4만 원) |
| 중급 모델 (예: Claude Sonnet 5.5, $2/$10 per 1M) | 약 $0.03 (≈42원) | 약 $30 (≈4만 원) | 약 $600 (≈84만 원) |
| Gemini 경량(Flash 계열) | 경량 Claude와 비슷한 수준으로 예상 — 계약 전 현행 단가 확인 필요 | | |

- 답변 원칙은 매번 같으므로 프롬프트 캐싱을 쓰면 입력 비용이 더 줄어든다.
- 서버: 재단 내부 서버면 0원, 외부 클라우드 소형 VM(2vCPU·4GB)이면 월 3~5만 원 수준.
- **합계(1단계)**: 경량 모델 기준 월 수천 원 + 서버비. 사용자별·전체 일일 상한으로 상한선을 둔다.
- 환율 1달러 ≈ 1,400원 가정. 실제 토큰 수는 2단계에서 로그로 측정해 다시 알려드린다.

## 2. 단계별 작업 계획 (설명서 9장 기준)

각 단계 끝에 실행 방법과 눌러볼 화면을 안내하고, 직접 확인 후 다음 단계로 넘어간다.

### 1단계 — 기반
- 프로젝트 골격(서버·화면·DB), `.env.example`, 실행 스크립트
- 로그인·가입 신청(소속 구분·기관명·지역·사업 유형만, 연락처 없음)·관리자 승인
- 권한 3단계(사용자/검수자/관리자), 10회 실패 잠금, 비밀번호 초기화·강제 변경
- 챗 화면(좌측 대화 목록, 세션 제목 자동 생성·검색, 다크모드) — 프로토타입 화면 이식
- AI 호출 서버 경유(지수 백오프 재시도, 실패 시 안내 + 1:1 문의 버튼)
- 1:1 문의함, 관리자 대화 열람(읽기 전용), 시스템 프롬프트 편집
- **확인 방법**: `npm run dev` → 관리자 로그인 → 가입 승인 → 사용자로 질문 몇 개

### 2단계 — 지식 적재와 검색
- 표준 Q&A 엑셀(‘통합질의’ 시트) 업로드: 확정/미검수 필터 설정, 버전·되돌리기, 전화번호·이메일 패턴 경고
- 답변 원칙·답변범위 외 목록 업로드
- 검색 색인(키워드 + 의미 혼합, 대표 질의 + 요지 체크리스트), 관련도 기준값
- 검색형 답변 + 구조화 출력(JSON) + 근거 카드(통합번호·대표 질의, 펼치면 전문)
- 사업 유형 선택(대화 시작 시) 및 해당 사업 우선 검색
- 지침·FAQ 업로드(PDF/TXT/MD → 조항 단위 분할, 쪽수·조항 번호 저장) — 파일 준비되면

### 3단계 — 라우팅·안전장치
- 답변 유형 4종(근거답변/연결형/답변범위외/근거없음)과 유형별 하단 버튼
- 지역앵커센터 연락처(17곳) 관리 화면, 사용자 지역별 연락처 표시
- ‘담당자에게 문의’ → 대화 자동 첨부해 1:1 문의함으로
- 개인정보 패턴(전화·이메일·주민번호·계좌) 전송 전 경고·가림
- 사용자별·전체 일일 질문 상한

### 4단계 — 평가
- 평가 질문집 엑셀(질문·기대 통합번호·기대 유형) 업로드·일괄 실행
- 적중률·연결 정확도 표, 실행 간 비교(프롬프트·데이터 변경 전후)

### 5단계 — 운영 루프
- 답변별 Good/Bad + 사유·의견
- 검토 대기함(Bad·근거 없음·범위 외 자동 수집 → 수정/추가/무시, 확정 즉시 검색 반영)
- 표준답안 편집기(목록·검색·필터·수정 이력·엑셀 가져오기/내보내기)
- 사용량·비용 화면(일별·기관별·토큰·비용·유형 비율·Good/Bad), 대화 필터(Bad·연결형)

### 6단계 — 마무리
- 지침 개정 공지 배너, 관련 답안 ‘재검수 필요’ 표시
- 감사 로그, 대화 보관 기간 자동 삭제
- Docker 배포 설정, 비개발자용 운영 설명서

## 3. 개발 전에 확인받을 사항

1. 위 기술 구성(React + Node.js + SQLite + 내장 임베딩, Docker 배포)으로 진행해도 되는지
2. 1단계 개발·테스트용 AI 제공사: Gemini 키가 있으면 Gemini로, 아니면 Claude로 시작(둘 다 교체 가능하게 만듦)
3. 최초 관리자 계정은 `.env`에 지정한 아이디·임시 비밀번호로 만들고 첫 로그인 시 강제 변경
4. 표준 Q&A 엑셀·답변 원칙·답변범위 외 목록은 2단계 시작 전에 이 저장소(비공개 확인 필요) 또는 대화로 전달 — 저장소가 공개라면 데이터 파일은 올리지 않음
